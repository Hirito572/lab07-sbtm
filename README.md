## 1. Зорилго

Уншлагын жагсаалт вэб аппликейшний чанарыг Session-Based Test Management (SBTM) аргаар шалгаж, тестийн charter, session report болон илэрсэн согогийн тайлангуудыг боловсруулах.

## 2. Файлын бүтэц

```text
lab07-sbtm/
├── README.md
├── charter.md
├── session-report.md
├── bugs/
│   ├── bug-01.md
│   ├── bug-02.md
│   ├── bug-03.md
│   └── bug-04.md
├── screenshots/
│   ├── bug-01.png
│   ├── bug-02.png
│   └── bug-03.png
├── evidence/
│   └── bug-04-curl.txt
└── .gitignore
```

## 3. Тестийн хамрах хүрээ

- Хоосон болон дутуу талбартай ном нэмэх
- Номын оны зөвшөөрөгдөх хязгаарыг шалгах
- Ижил гарчиг, зохиолчтой номыг давхардуулан нэмэхийг шалгах
- Номын жагсаалт болон үйлдлийн мессежийг шалгах
- API endpoint руу буруу JSON өгөгдөл илгээхэд ирэх HTTP хариуг шалгах

## 4. Сонгосон тестийн аяллууд

- **Couch Potato:** хоосон болон дутуу оролтыг шалгах
- **Boundary Testing:** номын оны хязгаарын утгуудыг шалгах
- **Fed-Ex:** өгөгдөл нэмэх болон давхардлын нөхцөлийг шалгах
- **Supermodel:** интерфэйсийн харагдах байдал, жагсаалт болон мессежийг шалгах
- **Saboteur:** API түвшний буруу JSON оролтыг шалгах

## 5. Илэрсэн согогууд

| ID | Согогийн тайлбар | Ноцтой байдал |
|---|---|---|
| BUG-01 | Бүх талбар хоосон байхад ном нэмэгдсэн | Major |
| BUG-02 | Зөвшөөрөгдөх доод хязгаараас бага буюу 999 онтой ном нэмэгдсэн | Major |
| BUG-03 | Ижил номыг давхардуулан нэмэх боломжтой | Major |
| BUG-04 | Буруу JSON оролтод HTTP 400-ийн оронд HTTP 200 OK буцаасан | Major |

Согог тус бүрийн дахин гаргах алхам, хүлээгдэж байсан үр дүн, бодит үр дүн болон ноцтой байдлыг `bugs/` хавтсанд тус тусад нь баримтжуулсан. UI согогуудын screenshot-ууд `screenshots/` хавтсанд, API шалгалтын `curl -i` үр дүн `evidence/bug-04-curl.txt` файлд хадгалагдсан.

## 6. Тестийн тайлан

`session-report.md` файлд тестийн зорилго, charter-ийн хураангуй, session-ийн тэмдэглэл, илэрсэн асуудлууд болон цагийн задаргааг оруулсан.

## 7. Дүгнэлт

Exploratory тестээр уншлагын жагсаалт аппликейшнд дөрвөн согог илрүүлж баримтжуулсан. BUG-01 нь бүх талбар хоосон байхад ном нэмэгдэж байгааг харуулсан. BUG-02 нь зөвшөөрөгдөх доод хязгаараас бага онтой ном бүртгэгдэж байгааг харуулсан. BUG-03 нь ижил гарчиг, зохиолчтой номыг давхардуулан нэмэх боломжтойг харуулсан. BUG-04 нь буруу JSON өгөгдөлд HTTP 400-ийн оронд HTTP 200 OK буцааж байгааг харуулсан. Эдгээр согогийг дахин гаргах алхам болон хүлээгдэж байсан, бодит үр дүнгээр нь тус тусад нь тайлагнасан. UI согогуудын screenshot-уудыг нотолгоо болгон хавсаргасан. API түвшний шалгалтын бүрэн `curl -i` үр дүнг `evidence/` хавтсанд хадгалсан. Цаашид оролтын баталгаажуулалт, оны хязгаар, давхардлын шалгалт болон API-ийн алдааны хариуг сайжруулж, дахин тестлэх шаардлагатай.
