## 3. Тестийн хамрах хүрээ

- Номын гарчиг, зохиолч, он талбарын хоосон болон буруу оролт
- Номын оны зөвшөөрөгдөх хязгаар
- Ижил гарчиг, зохиолчтой номыг давхардуулан нэмэх
- Интерфэйс, номын жагсаалт болон үйлдлийн мессеж
- Буруу JSON өгөгдөлд API-аас буцаах HTTP хариу

## 4. Тестийн аяллууд ба үр дүн

### 4.1 Couch Potato — Хоосон болон дутуу оролт

Гарчиг, зохиолч, он талбаруудыг хоосон орхиж ном нэмэхийг шалгасан. Хоосон мэдээлэлтэй ном амжилттай нэмэгдсэн тул **BUG-01** илэрсэн.

Энэ үр дүн нь хоосон талбарын шалгалт хангалтгүй байгааг харуулсан. Бүх боломжит дутуу талбарын хослолыг бүрэн шалгасан гэж дүгнэх боломжгүй.

### 4.2 Boundary Testing — Оны хязгаар

999 онтой ном нэмэхийг шалгасан. Зөвшөөрөгдөх доод хязгаараас бага утгыг систем хүлээн авсан тул **BUG-02** илэрсэн.

Энэ шалгалтаар 999 гэсэн утгыг баталгаажуулсан. 1000, 2100 болон зөвшөөрөгдөх хүрээнээс гадуурх бусад утгыг бүгдийг нь шалгасан гэж үзэхгүй.

### 4.3 Fed-Ex — Өгөгдөл нэмэх ба давхардал

`Clean Code`, `Robert C. Martin`, `2008` гэсэн мэдээллийг дахин оруулахад ижил ном жагсаалтад давхар нэмэгдсэн. Иймээс **BUG-03** илэрсэн.

Энэ үр дүн нь ижил мэдээлэлтэй номыг давхар бүртгэх боломжтойг харуулсан. Бусад номын мэдээлэл, хоосон зай болон үсгийн том, жижиг ялгаатай давхардлын нөхцөлийг бүрэн шалгаагүй.

### 4.4 Supermodel — Интерфэйсийн шалгалт

Интерфэйс, номын жагсаалт болон үйлдлийн мессежийг гараар ажигласан. Энэ аялалтай холбоотой тусдаа согог бүртгэгдээгүй.

Гэхдээ энэ нь интерфэйсийн бүх боломж алдаагүй гэсэн баталгаа биш. Дэлгэцийн хэмжээ, урт текст, өнгөний ялгарал, хүртээмж болон бусад харагдах байдлын нөхцөлийг бүрэн шалгаагүй.

### 4.5 Saboteur — API-ийн буруу оролт

`POST /api/books` endpoint руу буруу JSON өгөгдөл илгээсэн. Хүлээгдэж байсан HTTP 400 статусын оронд HTTP 200 OK буцсан тул **BUG-04** илэрсэн.

API хүсэлтийн бүтэн `curl -i` үр дүнг `evidence/bug-04-curl.txt` файлд хадгалсан.

## 6. Хамрах хүрээний хязгаар

Энэ ажлын хүрээнд ном нэмэх, хоосон оролт, оны хязгаар, давхардал болон буруу JSON API оролтод голлон анхаарсан. Хайлт, устгал, урт оролт, олон хэрэглэгчийн зэрэгцээ ажиллагаа болон бусад нэмэлт нөхцөлийг бүрэн шалгаагүй.

Тиймээс эдгээр шалгагдаагүй боломжийн чанарын талаар бүрэн дүгнэлт хийх боломжгүй. Дараагийн session-д эдгээр боломжид зориулсан тусдаа charter боловсруулж, тестийн хамрах хүрээг өргөжүүлэх шаардлагатай.

## 7. Playwright автомат тест ба хүний нүдээр хийх шалгалт

Playwright автомат тест нь урьдчилан тодорхойлсон алхам, оролт болон хүлээгдэж буй үр дүнг давтан шалгахад тохиромжтой. Жишээлбэл, хоосон талбар оруулахад ном нэмэгдэхгүй байх, оны хязгаарыг мөрдөх, давхардсан номыг хориглох зэрэг нөхцөлийг автомат тестээр тогтмол шалгаж болно.

Харин хүний нүдээр хийх exploratory тест нь интерфэйсийн харагдах байдал, мессежийн ойлгомжтой байдал, хэрэглэгчийн гэнэтийн үйлдэл болон урьдчилан таамаглаагүй асуудлыг ажиглахад давуу талтай.

Хоёр арга нь бие биеэ нөхдөг. Автомат тест нь давтагддаг шалгалтыг тогтвортой гүйцэтгэхэд, хүний шалгалт нь урьдчилан бүрэн тодорхойлоогүй асуудлыг илрүүлэхэд тустай. Энэ ажлын хүрээнд Playwright автомат тест ажиллуулсан нотолгоо байхгүй тул автомат тестийн гүйцэтгэлийн үр дүнг тайлагнаагүй.

## 8. Дүгнэлт

Couch Potato аяллаар хоосон талбартай ном нэмэгдэх согог илэрсэн. Boundary Testing аяллаар зөвшөөрөгдөх доод хязгаараас бага онтой ном нэмэгдэж байгааг илрүүлсэн. Fed-Ex аяллаар ижил номыг давхар бүртгэх боломжтойг тогтоосон. Saboteur аяллаар буруу JSON оролтод API HTTP 400-ийн оронд HTTP 200 OK буцааж байгааг илрүүлсэн. Supermodel аяллаар интерфэйсийг гараар ажигласан боловч тусдаа согог бүртгэгдээгүй бөгөөд энэ нь бүх интерфэйсийн нөхцөлийг шалгасан гэсэн үг биш юм. Тестийн хамрах хүрээ голчлон ном нэмэх болон буруу оролтын нөхцөлд төвлөрсөн. Хайлт, устгал, урт оролт болон бусад шалгагдаагүй нөхцөлийг дараагийн session-д хамруулах шаардлагатай. Цаашид Playwright автомат тестийг давтагддаг функциональ шалгалтад, хүний нүдээр хийх exploratory тестийг хэрэглэгчийн туршлага болон урьдчилан таамаглаагүй асуудлыг илрүүлэхэд ашиглах нь зүйтэй.
